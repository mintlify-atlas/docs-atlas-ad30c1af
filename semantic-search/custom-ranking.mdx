By default, the knowledge ranker picks the highest fused-score candidates after permission filtering, respecting the `maxResults` cap for each type. A backend module can replace this ranker entirely via the `knowledgeRankingExtensionPoint` from the module's `/alpha` export.

## Why Replace the Default Ranker

The default ranker does not consider factors beyond the retrieval score and type weights. That works well for most queries, but there are cases where domain knowledge improves results. For example, a large source with thousands of tickets that all reference the same system can crowd out a single runbook section even after weighting. A custom ranker can:

- Boost recently updated documents to surface fresh information first
- Favor specific document types for certain queries
- Apply business rules, such as prioritizing content from specific teams or lifecycle stages
- Demote stale content that is no longer authoritative

## Using the Extension Point

Import `knowledgeRankingExtensionPoint` from the `/alpha` subpath of the package and use it inside a `createBackendModule` call registered to the `assistants` plugin:

```ts
import { createBackendModule } from '@backstage/backend-plugin-api';
import { knowledgeRankingExtensionPoint } from '@drewswiredin/backstage-plugin-assistants-backend-module-semantic-search/alpha';

export default createBackendModule({
  pluginId: 'assistants',
  moduleId: 'knowledge-recency',
  register(env) {
    env.registerInit({
      deps: { ranking: knowledgeRankingExtensionPoint },
      async init({ ranking }) {
        ranking.setRanker(({ candidates, maxResults }) =>
          candidates
            .map(candidate => {
              const updated = Date.parse(String(candidate.metadata?.updated));
              const ageDays = (Date.now() - updated) / 86_400_000;
              const boost = ageDays < 90 ? 1.2 : 1;
              return { candidate, score: candidate.score * boost };
            })
            .sort((a, b) => b.score - a.score)
            .slice(0, maxResults)
            .map(({ candidate }) => candidate),
        );
      },
    });
  },
});
```

This example applies a 1.2× score multiplier to any result whose `metadata.updated` field is less than 90 days old, then returns the top `maxResults` candidates by adjusted score.

## Ranker Contract

The ranker function receives a single object with the following fields:

| Field | Description |
|---|---|
| `query` | The original question the user asked |
| `phrasings` | Alternative phrasings generated by the model (up to three) |
| `types` | The document types that were searched for this request |
| `candidates` | Up to 60 result candidates the caller has permission to read |
| `maxResults` | The maximum number of results to return |

Each candidate carries:

- **`score`** — the fused retrieval score after per-type weights have been applied
- **Rank in each retrieval list** — position in the semantic, keyword, rare-word, and fuzzy lists
- **`type`** — the document type string (e.g. `techdocs`, `jira`)
- **Entity ref** — for catalog and TechDocs results
- **`metadata`** — the short fields the collator attached to the document (strings, numbers, booleans), such as a ticket's status or a page's last update timestamp

The ranker must return an array of candidates from the input set, ordered by your preferred score. The framework enforces `maxResults` if you do not — but returning the correct number yourself is recommended.

## Security

The ranker runs after the permission check. The `candidates` array contains only documents the requesting user is already allowed to read; it is not possible for a ranker to surface content that was filtered out.

<Warning>
  Returning results that were not in the `candidates` input set has no effect — they are silently dropped before the response is sent. Only items from the original `candidates` array can appear in the final answer.
</Warning>

<Note>
  `knowledgeRankingExtensionPoint` is exported from the `/alpha` subpath, following Backstage's convention for extension points that may still change between minor versions. Import it as:

  ```ts
  import { knowledgeRankingExtensionPoint } from '@drewswiredin/backstage-plugin-assistants-backend-module-semantic-search/alpha';
  ```

  The stable `index` export remains unchanged.
</Note>
